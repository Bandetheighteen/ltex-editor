# Requirements: LaTeX Editor

**Defined:** 2026-10-08
**Core Value:** A stable, bug-free, and high-performance LaTeX editing experience that never shuts down unexpectedly and reliably renders PDFs side-by-side.

## v1 Requirements

### Frontend (SPA)

- [ ] **FRNT-01**: Side-by-side layout (editor on left, PDF viewer on right).
- [ ] **FRNT-02**: Adapter layer that detects environment (Tauri vs Browser) and dispatches commands.
- [ ] **FRNT-03**: Debounced auto-compilation triggers.
- [ ] **FRNT-04**: SyncTeX click handling (click on PDF -> scroll to editor line; click on editor line -> scroll PDF).

### Native Shell (Tauri)

- [ ] **NATV-01**: Initialize Tauri v2 application framing the SPA.
- [ ] **NATV-02**: Implement `compile_latex` Tauri command (spawns `pdflatex` as child process).
- [ ] **NATV-03**: Implement `synctex` Tauri command (spawns `synctex` CLI).
- [ ] **NATV-04**: Robust child process lifecycle management (no zombie `pdflatex` processes).
- [ ] **NATV-05**: Maintain stable memory profile under repeated compilations.

### Web Server (Backend)

- [ ] **WEBS-01**: HTTP server (Node.js/Fastify or Rust/Axum) serving the `public` SPA.
- [ ] **WEBS-02**: `/api/compile` endpoint that mirrors `compile_latex` logic.
- [ ] **WEBS-03**: `/api/synctex` endpoint that mirrors `synctex` logic.
- [ ] **WEBS-04**: Robust process cleanup and timeout handling on the server.

## v2 Requirements

### Editor Enhancements

- **EDIT-01**: Advanced auto-completion using a LaTeX Language Server.
- **EDIT-02**: Custom snippets and macros UI.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Cloud LaTeX Compilation | Compilation will remain local to rely on the user's local MiKTeX/TeX Live installation to keep infrastructure simple and offline-capable. |
| Full IDE features (Git, extensions) | Keeping it a "small IDE-like setup" as requested, to preserve performance and prevent bloat. |
