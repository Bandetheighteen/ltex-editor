# Roadmap: LaTeX Editor

## Overview

This roadmap defines the journey to migrate the unstable Node.js/Electron LaTeX IDE to a highly stable, dual-target application using Tauri (Rust) for the native shell and a companion web server, sharing a common React/Vite frontend.

## Phases

- [x] **Phase 1: Frontend Adapter Layer** - Refactor existing frontend to dispatch commands environment-agnostically.
- [x] **Phase 2: Tauri Application Setup** - Initialize the Tauri v2 project and frame the frontend.
- [x] **Phase 3: Native Compilation Support** - Implement `pdflatex` compilation via Rust IPC.
- [x] **Phase 4: Native SyncTeX Support** - Implement `synctex` handling in Rust and UI mapping.
- [x] **Phase 5: Web Server Setup** - Scaffold the Node.js/Rust web server serving the frontend.
- [x] **Phase 6: Web Server APIs** - Implement the HTTP endpoints for compilation and SyncTeX.

## Phase Details

### Phase 1: Frontend Adapter Layer
**Goal**: Refactor the existing `public/` frontend code to abstract backend commands (Compile, SyncTeX) behind an environment-aware adapter layer.
**Depends on**: Nothing (first phase)
**Requirements**: [FRNT-01, FRNT-02, FRNT-03]
**Success Criteria** (what must be TRUE):
  1. Frontend can detect if it's running inside Tauri (`window.__TAURI__`) or a browser.
  2. Compilation and SyncTeX calls are routed through a central `invokeCommand` wrapper.
  3. UI handles loading states and debounce logic.
**Plans**: 2 plans

Plans:
- [x] 01-01: Extract compilation logic from frontend and create adapter
- [x] 01-02: Implement debounce and error handling UI states

### Phase 2: Tauri Application Setup
**Goal**: Initialize the Rust Tauri v2 project and bundle the frontend SPA.
**Depends on**: Phase 1
**Requirements**: [NATV-01]
**Success Criteria** (what must be TRUE):
  1. `cargo tauri dev` launches a native window showing the editor.
  2. Release builds produce a standalone `.exe`.
**Plans**: 1 plan

Plans:
- [x] 02-01: Initialize Tauri v2 project and configure `tauri.conf.json`

### Phase 3: Native Compilation Support
**Goal**: Implement local LaTeX compilation in the Tauri backend using Rust's `std::process::Command`.
**Depends on**: Phase 2
**Requirements**: [NATV-02, NATV-04, NATV-05]
**Success Criteria** (what must be TRUE):
  1. Triggering compilation from the native UI successfully runs `pdflatex`.
  2. The generated PDF is returned to the frontend and rendered.
  3. No zombie `pdflatex` processes are left running on failure or app close.
**Plans**: 2 plans

Plans:
- [x] 03-01: Implement `compile_latex` Tauri command and async process handling
- [x] 03-02: Integrate PDF returning mechanism and memory/zombie safeguards

### Phase 4: Native SyncTeX Support
**Goal**: Add SyncTeX to the native app to allow bidirectional source-to-PDF mapping.
**Depends on**: Phase 3
**Requirements**: [FRNT-04, NATV-03]
**Success Criteria** (what must be TRUE):
  1. Clicking a line in the Monaco/CodeMirror editor scrolls the PDF.
  2. Clicking the PDF highlights the source line.
**Plans**: 2 plans

Plans:
- [x] 04-01: Implement `synctex` Tauri command wrapping the CLI
- [x] 04-02: Wire SyncTeX UI events in the frontend

### Phase 5: Web Server Setup
**Goal**: Replace the old `server.js` with a clean, modular server implementation that serves the frontend.
**Depends on**: Phase 1
**Requirements**: [WEBS-01]
**Success Criteria** (what must be TRUE):
  1. Starting the server exposes the web UI at `localhost:3000`.
**Plans**: 1 plan

Plans:
- [x] 05-01: Initialize server and static file serving routes

### Phase 6: Web Server APIs
**Goal**: Implement the HTTP endpoints for `pdflatex` and `synctex` execution.
**Depends on**: Phase 5
**Requirements**: [WEBS-02, WEBS-03, WEBS-04]
**Success Criteria** (what must be TRUE):
  1. Browser UI successfully triggers compilation and renders the PDF via API.
  2. Browser UI successfully uses SyncTeX.
  3. HTTP routes enforce timeouts to prevent long-running hanging processes.
**Plans**: 2 plans

Plans:
- [x] 06-01: Implement POST `/api/compile` with timeout and cleanup
- [x] 06-02: Implement POST `/api/synctex` logic
